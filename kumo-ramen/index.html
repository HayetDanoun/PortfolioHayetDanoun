Sous le capot

Deux interfaces, un seul état partagé. Chaque action côté client ou côté cuisine passe par une machine à états de la commande.

Ce qui tourne ici

  • JavaScript natif, sans framework, avec une machine à états : nouvelle → en préparation → prête → remise.
  • Synchronisation en temps réel entre onglets avec BroadcastChannel : ouvrez cette page dans un deuxième onglet, les deux restent synchronisés.
  • Créneaux de retrait calculés selon la charge de la cuisine (4 commandes max par quart d'heure).
  • Temps d'attente estimé à partir des commandes en cours et du temps de préparation de chaque plat.
  • Ruptures en direct : un plat retiré en cuisine devient indisponible côté client immédiatement.

Version production : Symfony + Mercure

Côté serveur, Symfony publie chaque changement d'état sur un hub Mercure ; les écrans s'y abonnent en Server-Sent Events.

// src/Controller/KitchenController.php #[Route('/api/orders/{id}/ready', methods: ['POST'])] public function ready(Order $order, WorkflowInterface $orderStateMachine, HubInterface $hub): JsonResponse { $orderStateMachine->apply($order, 'mark_ready'); $this->em->flush(); $hub->publish(new Update( "/orders/{$order->getId()}", $this->serializer->serialize($order, 'json', ['groups' => 'order:status']) )); return $this->json($order, context: ['groups' => 'order:status']); } // côté client const es = new EventSource(`${hub}?topic=/orders/${id}`); es.onmessage = e => renderTracker(JSON.parse(e.data));
